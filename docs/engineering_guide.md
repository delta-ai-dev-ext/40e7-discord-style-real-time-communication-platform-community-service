# community_service — Engineering Guide

Persistent technical memory for the Coding Agent and future maintainers. Behavioral spec: `docs/user_stories.md`. Contract: `docs/openapi_spec.yaml`. Clean architecture & DB schema: `docs/architecture.md`.

## Runtime & Toolchain

| Aspect | Choice |
|---|---|
| Language | TypeScript (strict mode, `moduleResolution: "bundler"`, target ES2020+) |
| Runtime | **Bun** — execute with `bun` only; never `node`; no NodeJS-only dependencies or CommonJS |
| Package manager | `bun` (add deps via `bun add` / `bun add -d`; never `npm`) |
| Entry point | `src/index.ts` (Elysia app factory + server start) |
| Build/test entrypoints | `Makefile` targets only: `make dev`, `make test`, `make build`, `make run`, `make lint` |

`package.json` MUST set `"type": "module"` (ES modules only). Test coverage thresholds ≥ 80% (line/branch/function/statement) via `bunfig.toml`. Container builds use the `oven/bun:1` multi-stage Dockerfile pattern with `--frozen-lockfile` and run as non-root (`oven/bun:1-slim`, `bun run --smol`). Image builds are performed by CI — never inside the agent runtime (no Docker daemon).

## Libraries & External Provider SDKs

| Concern | Package / Library | Source | Usage Notes |
|---|---|---|---|
| HTTP framework | `elysia` | language-skill | Bun-native, TypeScript-first. Used for all routes incl. `/healthz`, `/readyz`; thin handlers delegating to services |
| Validation | `zod` | language-skill | All boundaries: request bodies, query/path params, env config (`src/config.ts`), and parsing of anything crossing the process boundary |
| ORM | `drizzle-orm` | language-skill | Typed schema in `src/repositories/`; migrations generated by drizzle-kit; parameterized queries only |
| PostgreSQL driver | `pg` | language-skill | `drizzle-orm/node-postgres` adapter over a `pg` Pool configured from `DATABASE_URL` |
| Kafka client | `kafkajs` | language-skill | Producer for `community_events` + `community_invite_events`; idempotent producer enabled; SASL/TLS via env vars when configured |
| Logging | `winston` | language-skill | JSON structured logs to stdout; levels error/warn/info/debug; never `console.log` in production code |
| Metrics | `prom-client` | language-skill | All metrics from `docs/architecture.md` §7 registered at startup; expose `/metrics` |
| Random IDs / invite codes | `crypto.getRandomValues()` (Bun/Web Crypto) | language-skill | UUIDv4 generation and URL-safe invite codes; NEVER the `uuid` package or `Math.random()` |
| HTTP client | `fetch` (native Bun/Web Standard) | language-skill | No external HTTP client dependency (`axios`, `node-fetch` forbidden) |
| Date utils | `date-fns` | language-skill | Timeout/expiry arithmetic and formatting |
| Testing | `bun:test` | language-skill | Only approved runner; `*.test.ts` under `tests/` |
| Mocking | `mock()` from `bun:test` | language-skill | Mock DB pool, Kafka producer, outbox relay; reset after every test |
| External providers | — (none) | SYSTEM_DESIGN | This service integrates **no** third-party providers. Clerk JWTs are verified **offline** against Clerk's published JWKS (see below) |

**Clerk JWT verification (in-house, no SDK):** verify session JWTs offline using the Clerk instance's published public key/JWKS (`CLERK_JWKS_URL`, `CLERK_ISSUER`). Claims consumed: `sub` (platform `user_id`), `username`, `email`. Implement as middleware (JWT signature + `exp` + `iss` verification) rather than a Clerk backend SDK, since no Clerk server-side operation (webhooks, user writes) is performed by this service. If a maintained Clerk TS verification library is adopted later, record it here and in Pinned Decisions.

## Kubernetes Lifecycle & Probes

- **Statelessness**: strictly stateless — no session state, no mutable files on disk. All durable state lives in PostgreSQL; async delivery through Kafka. Safe with `replicas > 1`.
- **`GET /healthz` (liveness)**: lightweight; returns `200` while the event loop responds. MUST NOT fail on transient PostgreSQL/Kafka hiccups.
- **`GET /readyz` (readiness)**: `200` only when the PostgreSQL pool responds and the Kafka producer is connected; `503` once shutdown starts. Readiness gates traffic from the load balancer and internal callers.
- **`SIGTERM`/`SIGINT` graceful shutdown**, in order:
  1. Flip readiness to `503` immediately (stop new traffic routing).
  2. Stop accepting new HTTP requests; pause the outbox relay loop (never mid-transaction — it is transaction-safe by design).
  3. Drain in-flight HTTP requests within a bounded shutdown timeout (15–30 s; internal access checks must be far faster than this).
  4. Close the PostgreSQL pool and the Kafka producer cleanly; exit `0`.
- **Startup ordering**: fail fast — config validated (Zod) before binding the port; DB pool + producer initialized before `/readyz` reports healthy. Outbox relay starts after the producer is connected.

## Testing Strategy

- **Structure**: `tests/unit/` (permission resolution engine, invite state machine, moderation hierarchy guards, service logic), `tests/integration/` (route → service → repository with mocked DB/producer), `tests/mocks/` (shared fakes/fixtures).
- **Unit tests** MUST NOT touch the network or real infrastructure: mock the DB pool (in-memory fake repository implementations or `mock()`-ed drizzle calls), mock the Kafka producer, and stub the outbox relay.
- **Integration tests** exercise the Elysia app in-process with mocked repositories and a mock producer asserting outbox row insertion semantics (state change + outbox row in the same transaction boundary).
- **Permission engine tests are the crown jewels**: table-driven cases covering the full resolution order (base roles → `@everyone` overwrite → role overwrites → member overwrite), owner/`ADMINISTRATOR` implicit permissions, hierarchy guards, and self-grant prevention.
- **Determinism & parallelism**: no shared mutable state between tests; fixed clocks injected for expiry logic (timeout 28-day cap, invite expiry, ban expiry); tests run in parallel via `bun test`.
- **Coverage**: ≥ 80% line/branch/function/statement (`bunfig.toml` thresholds); `make test` is the single entrypoint (`bun test --coverage`).
- **Mocks reset**: every `mock()` is restored after its test; no test depends on execution order.

## Coding Conventions & Project Structure

```
community_service/
├── docs/                        # this spec set
├── src/
│   ├── index.ts                 # app factory + server start + signal handling
│   ├── config.ts                # Zod-validated env config (12-factor)
│   ├── routes/                  # Elysia routers grouped by resource (communities, channels, roles, members, invites, moderation, audit, internal, probes)
│   ├── controllers/             # thin request handling: validate → call service → map errors
│   ├── services/                # business logic (permissions engine, invites, moderation, audit writer); no direct I/O
│   ├── repositories/            # drizzle schema + typed data access
│   ├── events/                  # outbox writer, relay loop, Kafka producer wrapper, event schema definitions
│   └── models/                  # Zod schemas + TypeScript types shared by routes/services
├── tests/
│   ├── unit/
│   ├── integration/
│   └── mocks/
├── Makefile, Dockerfile, package.json, bun.lockb, tsconfig.json, bunfig.toml, .gitignore, README.md
```

- **Layering**: `routes → controllers → services → repositories`. Services never import Elysia types; repositories never contain business rules.
- **Errors**: single error contract `{error: {code, message, details?}}` with stable machine-readable codes (`missing_permission`, `invite_invalid`, `invite_expired`, `invite_exhausted`, `invite_revoked`, `banned`, `member_timed_out`, `validation_error`, `not_found`). Handlers map domain errors to HTTP statuses; services throw typed domain errors; stack traces never reach clients.
- **Typing**: `strict: true`; branded ID types (`UserId`, `CommunityId`, …) where cross-entity confusion is plausible; discriminated unions for invite states and event payloads.
- **Transactions**: any change accompanied by an audit entry and/or outbox row MUST run in one transaction (see `docs/architecture.md` §5). Prepared statements / ORM parameterization only — never string-interpolated SQL.
- **ES modules only**; no CommonJS; no `dotenv` in production; no `console.log`.

## Configuration & Secrets Management

12-factor: everything from environment variables, validated by a Zod schema in `src/config.ts` at startup (fail fast with a structured error log). No `.env` in production (local dev only, git-ignored). Production secrets arrive via Kubernetes-mounted env vars.

| Variable | Required | Purpose |
|---|---|---|
| `PORT` | no (default 3000) | HTTP listen port |
| `DATABASE_URL` | **yes** | PostgreSQL connection string (portable form) |
| `KAFKA_BROKERS` | **yes** | Comma-separated broker list |
| `KAFKA_CLIENT_ID` | no (default `community_service`) | Kafka client identifier |
| `KAFKA_SASL_MECHANISM` / `KAFKA_SASL_USERNAME` / `KAFKA_SASL_PASSWORD` | no | SASL when the cluster requires it |
| `KAFKA_TLS_ENABLED` | no | TLS to brokers |
| `CLERK_JWKS_URL` | **yes** | Clerk published JWKS for offline JWT verification |
| `CLERK_ISSUER` | **yes** | Expected JWT `iss` claim |
| `INTERNAL_SERVICE_TOKENS` | **yes** | Comma-separated per-caller shared secrets for `/internal/v1/*`; rotate via K8s secrets |
| `LOG_LEVEL` | no (default `info`) | `debug\|info\|warn\|error` |
| `SHUTDOWN_TIMEOUT_MS` | no (default 20000) | Graceful drain budget |

Never log secrets or full tokens. `INTERNAL_SERVICE_TOKENS` are compared with constant-time equality. `.env`/`.env.local` and `*.pem`/`*.key` belong in `.gitignore`.

## Observability & Logging Conventions

- **Structured JSON logs** (winston, stdout): fields `timestamp`, `level`, `service_name: "community_service"`, `trace_id`, `operation`, `status`, plus duration for external calls (DB queries, Kafka produces). Errors log stack traces server-side only.
- **Trace propagation**: read W3C `traceparent` on inbound HTTP; generate one when absent; propagate into every outbox event envelope (`trace_parent`) and every downstream log line. Internal access checks MUST log with the caller's trace id.
- **Metrics registration** (prom-client, low-cardinality labels only — never `user_id`/`community_id`/`channel_id`/`request_id`):
  - Business: `community_created_total`, `community_invites_created_total{kind}`, `community_invite_accepts_total{result}`, `community_members_joined_total`, `community_moderation_actions_total{action}`, `community_audit_log_views_total`.
  - Technical: `http_request_duration_seconds{route,method,status_class}`, `community_access_check_duration_seconds{endpoint}`, `community_outbox_lag_seconds` (gauge, age of oldest pending outbox row — alert on SLO breach), `kafka_produce_errors_total{topic}`.
- **SLOs to protect**: internal access p95 < 25 ms & 99.95% availability; public API p95 < 200 ms; outbox publish lag p95 < 2 s.
